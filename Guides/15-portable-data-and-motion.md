# 便携数据、保存与交互动效

## 数据目录

Wonder 使用程序旁的 `WonderData`，不受快捷方式“起始位置”影响，也不会在无法写入时自动改用其他目录。

| 文件或目录 | 用途 |
| --- | --- |
| `settings.json` | 外观、桌面交互与实例排列偏好 |
| `workspace.json` | 功能区、快捷方式、位置与组件状态 |
| `instances.json` | 实例登记、游戏全局设置和实例覆盖 |
| `accounts.dat` | 加密账户资料与凭据 |
| `cache/` | 启动所需的 Wonder 缓存 |
| `plugins/` | 预留目录；目前不表示已经支持第三方插件运行 |
| `.instance.lock` | 同一数据目录的进程协调文件，不包含账户凭据 |

备份时先正常退出启动器，再复制整个 `WonderData`。布局和实例登记可随程序移动，但账户库绑定原 Windows 用户和系统，换电脑后需重新登录。游戏文件可能仍位于独立目录，不包含在这份数据备份中。不要公开账户库、数据备份或游戏日志。

同一数据目录只允许一个启动器进程写入。再次启动会尝试激活已有窗口；不能激活时会提示已有实例运行并退出。不同便携目录可独立运行。运行期间不要删除或替换 `.instance.lock`；退出后锁由系统释放，无需手动删除文件。

## 自动保存与错误处理

布局和便笺的连续修改在约 **350 毫秒没有新编辑后**合并保存。内容先在各入口间立即同步，再依次在后台写入，输入无需等待磁盘。

正常关闭会等待最新内容写完。若保存失败，窗口保持打开并显示“布局尚未保存”；检查写入权限、磁盘空间及文件占用后，可重试保存或再次关闭。强制结束进程或断电可能丢失尚未写入的修改。

读取损坏布局失败时保留原文件，不自动覆盖。工作区和实例索引保存时先写同目录临时文件，再刷新并关闭文件后替换；提交前失败会保留旧文件。残留 `.tmp` 文件不会被自动当作正式数据载入。保存错误会保留最初的失败原因，并可能附带清理失败的残留路径。这些措施不能保证断电时的事务完整性。

外观与交互设置的恢复方法见[设置组件](14-settings-component.md)；游戏全局与实例表单需要分别点击保存，见[分类设置](21-settings-pages-and-instance-cards.md)。

## 侧栏与点击动效

侧栏开合约 190 毫秒，邻区与分隔边同步移动；鼠标迅速返回时会从当前状态反向展开。手动拖动展开侧栏朝内的边缘，实际可见尺寸比起点增加超过 8 DIP 时，提示“松开恢复为普通功能区”；未达到条件时提示保持侧栏。缩小侧栏不会保存新的展开尺寸。

成功点击组件后显示约 350 毫秒的波纹，鼠标点击从释放位置展开，Enter 或 Space 从中心展开。波纹限制在组件轮廓内，不影响短按、长按或拖动判定，也不延迟执行动作。更多桌面操作见[桌面与功能区](13-wonder-ui-foundation.md)。
