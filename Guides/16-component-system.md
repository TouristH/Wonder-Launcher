# 通用组件系统

设计日期：2026-10-21，实施更新：2026-10-22。承接产品目标与上一轮 UI 框架评估。本轮实施范围是组件接入、状态、动作和生命周期，以及设置、便笺、启动器状态三个实际组件。

## 保留的产品规则

- 桌面分区、侧栏、拖放、主题、点击波纹、空桌面与设置窗口继续沿用。
- 组件定义描述一种能力；组件库中的应用实例持有数据；桌面快捷方式引用应用实例，并独立保存位置。
- 同一应用的组件库入口及全部快捷方式共享状态。不同应用实例可以使用同一定义并保持数据独立。
- 移除快捷方式、清空桌面、关闭组件库都不删除应用数据。
- 不读取或恢复前身产品的账号、布局与插件。保留本次 Wonder 预览版本的布局升级路径。

## 接入边界

采用稳定的字符串 DefinitionId、显式注册表和应用运行宿主。新增组件只需实现组件契约并登记，不再向工作区、区域或组件库添加类型分支。

注册信息包含标题、说明、自然尺寸与展示方式。应用运行实例负责动作和状态；Avalonia 适配层负责控件及输入；工作区只负责布局与拖放。设置保留原有存储及窗口服务，通过动作回调接入。

相比只扩大枚举与 switch，此方案能验证新增组件不修改工作区的目标。完整插件进程、包管理和权限系统另按产品路线实施，本轮不将内置注册表宣传为已完成插件生态。

`Wonder.Extensibility.Contracts` 提供 `ComponentDefinition`、`IComponentState` 和 `IComponentRuntime`。当前回调是同步的，应执行短操作；它没有授权后台工作或提供进程隔离。原生展示适配器仍是 Desktop 的内部机制。

在 `Components/BuiltInComponents.cs` 注册定义、运行实例工厂及展示工厂。定义包含自然宽高及归一化轮廓；运行实例通过 `IComponentState.Set` 写入共享数据，通过 `Changed` 通知临时展示值；展示内容通过 `ComponentPresentationContext.Invoke` 分发动作。新增类型不需要修改 `WorkspaceView`、`AreaView` 或 `ComponentLibraryView`。已用单独的测试组件验证该接入路径。

## 状态与生命周期

每个应用 ID 对应一个运行实例。视图附着、隐藏与移除分别通知宿主；没有可见视图时暂停定时活动，重新显示时恢复。关闭主窗口释放宿主。拖动预览只读取展示信息，不启动任务、定时器或新的业务实例。

组件加载、动作或刷新失败只影响该应用，显示可重试的占位。重试不能重复注册订阅；已经离开的视图不能接收过期更新。未知定义保留其标识、状态与快捷方式，在占位中说明不可用。

便笺提供文字输入、自动保存和多视图同步。文字编辑、选择、滚动不触发工作区长按拖动，标题区域保留移动入口。启动器状态展示版本、运行环境、数据位置与运行时长；隐藏后暂停刷新。

## 存储

新版布局使用 v3，保存 DefinitionId 和应用状态。应用状态有条目、键长、值长限制，继续使用现有 2 MiB 文件上限及原子替换。

读取 v1/v2 时将设置 kind=3 转换为稳定标识，严格校验后清除已移除的三个演示组件。v1 坐标必须等首次有效布局后完成转换，不能因提前升级版本而跳过。未知旧数字种类依然报错。未知的新字符串标识可往返保存。

读取失败保留原文件；自动保存失败保留当前会话内容与错误提示。初始化注册组件不会给用户清空的桌面补入快捷方式。

v1 文档在坐标转换完成前拒绝写回；`WorkspaceView` 完成首次布局转换后才允许写入 v3。保存成功后才更新内存中的版本标记。结构、重复字段、状态限制和应用引用均在替换原文件前校验。

## 验收

1. 设置所有入口仍复用原窗口；三种组件可搜索、拖入、移动与移除。
2. 便笺在组件库与多个快捷方式之间同步，重启保留；独立应用实例互不覆盖。
3. 输入、长按拖动、拖回组件库、Esc 取消与侧栏收起互不干扰。
4. 自定义测试组件可以通过注册接入，无需修改工作区。
5. 未知定义、加载失败、动作失败与重试不会破坏其他组件。
6. 没有可见视图及关闭窗口后释放订阅与定时器；预览没有运行副作用。
7. 现有布局、DPI 和主题回归通过，生成新的单文件程序。Headless 截图与自动化不冒充原生多屏验收。

布局撤销/重做、统一窗口与后台任务管理、用户调整组件尺寸及完整插件沙箱仍属于后续独立工作。
