# 0.5.1 实例选择与目录操作

日期：2026-10-24。

## 交互

实例管理负责浏览、选择和设置。点击实例卡片选中启动目标并高亮，停留在列表；右侧设置按钮打开该实例详情，不改变启动目标。启动游戏组件只负责当前目标的启动与运行状态，离线用户名在游戏全局设置中修改。

保留列表/网格切换和排列偏好。网格采用紧凑宽度和内容决定的高度，不强制撑成大正方形；名称、版本和路径换行显示，去掉多余留白。设置、删除按钮与选择区域分别响应，避免点击按钮误选实例。

## 文件操作

实例和游戏目录卡片均有设置与删除按钮。目录设置以父目录路径和目录昵称（实际文件夹名）形成目标，实际移动或重命名文件夹，并同步 Wonder 索引。

用户已选择删除策略为系统回收站。删除确认必须显示名称、完整路径和范围，精确输入小写 `sure` 才可执行；取消、空值、其他大小写都不执行。不支持回收时报告失败，不改为永久删除。实例删除需按来源定位独立目录，不能把共享游戏根目录误认为实例目录。涉及运行中实例、共享依赖、无法安全确定的目录或路径变化时拒绝文件操作并给出原因。

功能测试只使用临时目录；系统回收站另用一次性测试文件夹验证，不删除、移动或重命名用户现有游戏。发布前备份既有数据，发布后校验未发生变化。

游戏目录独立保存登记。删除最后一个实例后，空目录卡片仍保留，重启后也能重新扫描、改名或单独回收整个目录；只有删除目录本身才移除目录登记。旧索引会从已有实例补齐目录列表。

当前支持 Windows 系统回收站与同一磁盘内的目录移动/重命名。跨磁盘移动、网络路径、链接目录、系统/用户主目录以及无法确认的游戏根目录会明确拒绝。其他实例仍在使用的版本或目录也不能回收；独立实例目录之外的共享资源、存档目录保持原样，并在删除确认中说明。

目录移动后，Wonder 保留实例 ID、自定义名称和覆盖设置，重读来源时按移动记录调整原来的绝对路径，防止重复登记。其他启动器的配置文件内容保持原样，在原启动器中使用时可能仍需调整旧的绝对路径。移动完成但索引写入失败时尝试移回原位置；回收完成但索引写入失败时保留原登记、阻止进一步修改，并提示从系统回收站还原。

Windows 实现使用系统 [IFileOperation](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nn-shobjidl_core-ifileoperation)，在删除前回调中拒绝永久删除分支；回调失败会取消操作，行为依据 [PreDeleteItem 文档](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileoperationprogresssink-predeleteitem)。
