# 双层皮肤、已选披风与账户头像

适用版本：0.7.2。

## 使用

账户管理组件左侧直接显示当前账户的皮肤头像，包含头部基础层与帽子、头发等外层。切换账户、刷新资料或修改离线皮肤后更新；没有增加新的组件或改变已有桌面布局。悬停头像可查看加载说明。

正版和第三方详情显示角色正面、背面，以及独立的“已选披风”预览。全身预览显示头、上衣、袖子、裤腿外层，支持透明区域、经典/纤细模型和 64×32 旧版皮肤；旧版缺少的左侧肢体按镜像规则绘制。角色背面显示已佩戴披风，未选择披风时明确标记。正版皮肤及本地上传仍使用 64×64 或 64×32 PNG，正版披风为 64×32 PNG，单张不超过 1 MiB。

第三方账户同时支持 **HD 皮肤与披风**：PNG 宽度为 64 的整数倍，皮肤为正方形（例如 128×128、256×256、512×512）或宽高比 2:1 的旧版布局，披风为宽高比 2:1（例如 128×64、256×128、512×256）。最大宽度 4096 像素，单张不超过 16 MiB。头像、全身正背面、透明外层和独立披风卡片会按原图分辨率取样，不先缩成 64 像素；皮肤与披风可以使用不同分辨率。无需启用额外开关，在认证网站选择 HD 外观后回到启动器点击“刷新资料”即可。

第三方账户升级后先在账户中心点击“刷新资料”，以取得此前版本未保存的皮肤和披风地址。在“选择皮肤 · 打开认证网站”中更改外观后，再回到启动器刷新资料。第三方披风由对应网站管理；启动器展示服务器提供的当前披风，不将它伪装为正版自有披风。

离线头像读取所选实例已经安装的默认皮肤纹理。缺少纹理或没有选择实例时显示示意头像，并在悬停说明中标记。此预览不安装额外资源、不修改游戏 JAR；离线 UUID 与版本差异仍遵循[默认皮肤说明](28-login-diagnostics-and-default-skins.md)。

## 数据和网络边界

第三方登录、重新登录和刷新资料后，向所选认证服务器的 `sessionserver/session/minecraft/profile/{uuid}` 查询公开角色属性，校验外层角色 ID 与 Base64 纹理资料中的角色 ID 一致。读取 `SKIN`、模型和当前 `CAPE`，不发送密码、access token 或 client token。协议参考 [authlib-injector 官方 Yggdrasil 规范](https://yushijinhun.github.io/authlib-injector/en/yggdrasil-server-technical-specification.html)。

正版纹理继续限制为官方纹理域名；第三方纹理允许认证服务器声明的自定义 HTTPS 域名，但拒绝用户名密码、查询参数、片段和控制字符。所有纹理请求均不携带账号凭据，不跟随重定向，并限制时间、响应大小、PNG 尺寸与容器。只提供 HTTP 或不符合这些条件的地址不会自动降低安全要求；可让服务维护者提供 HTTPS 纹理地址。

第三方纹理默认拒绝回环、私网、本地名称及特殊用途网络地址。域名在建立连接时解析，所有返回地址均需通过检查，再直接连接已检查的 IP；许可不会被其他账户或撤销后的请求继承。使用内网皮肤服务时，在该账户详情的纹理来源设置中逐个添加明确的 HTTPS 来源，操作说明见[账户管理](26-account-management.md)。皮肤、披风与头像共用该账户的许可；其他账户、端口和子域不会继承。

第三方纹理采用直接连接，不使用系统 HTTP 代理，也不发送 Cookie 或自动凭据；需要代理才能访问的纹理可能无法预览。来源许可仅放行该来源的内网或回环单播目标，仍要求有效的 HTTPS 证书，不放行未指定地址、多播或广播。认证服务器发现、登录和官方纹理保持各自原有网络路径。

外观资料保存在现有加密账户库，图片仅在预览控件内存中使用，不写入工作区布局。预览失败不撤销成功的第三方登录；刷新失败时保留最后可用资料。有效的空纹理资料会清除之前的外观。切换账户先清空旧纹理，关闭控件取消请求并释放图片，迟到的结果不会覆盖新账户或本地预览。
